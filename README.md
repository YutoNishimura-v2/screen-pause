# ひと呼吸

選んだアプリを決めた時間に制限し、開く前に10秒おく iPhone・iPad アプリです。ホームには「今日、開かずに戻れた回数」を表示します。日付が変わると日次の回数はゼロに戻り、連続日数は一時解除せずに終えた制限日を数えます。設定と記録は端末内に保存します。

## ビルド

iOS 17 以降。Mac で XcodeGen と Xcode を使い、アプリと5つの拡張をビルドします。

```sh
xcodegen generate
xcodebuild -project ScreenPause.xcodeproj -scheme ScreenPause -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

`land.json` の Node チェックは、初週との比較、ウィジェットの日付切り替えと制限状態、待機時間の境界も検査します。

## 画面の撮影

既定ブランチのアプリ変更時、または GitHub Actions の「画面の撮影」を既定ブランチで手動実行すると、iPhone シミュレータでライト・ダーク各7枚を撮影します。成功時は `ci-shots` ブランチの `index.md` から画像を確認できます。

ローカルでは XcodeGen でプロジェクトを生成し、`ScreenPauseScreenshots` スキームのテストを iPhone シミュレータで実行します。デバッグ用シミュレータの `--screenshot-demo` は、許可・対象アプリ・記録・購入状態をデモ用に差し替えます。制限画面はアプリ内のプレビューです。

## 購入画面の確認

1. Xcode のスキームで「実行 → オプション」の StoreKit 設定が `ScreenPause.storekit` になっていることを確認します。「実行 → 引数」に `--storekit-test` を追加し、デバッグ用シミュレータで起動します。
2. 「2件目の予定を追加」を押し、年額が選択済みで、対象なら14日間無料とその後の年額が表示されることを確認します。月額と買い切りも選択できます。表示価格は StoreKit のローカル設定に入れた仮の値です。
3. テスト購入後に購入画面が閉じ、「Pro 利用中」になることを確認します。Xcode の StoreKit トランザクション管理で購入を取り消し、「無料プラン」に戻ることを確認します。購入履歴のある無料状態から「購入を復元」も確認します。

App Store に出す前に、[提出チェックリスト](docs/release-checklist.md)に沿って商品と年額の無料オファーを登録します。利用規約とプライバシーポリシーの公開先は、本体のビルド設定 `SCREEN_PAUSE_LEGAL_BASE_URL` で指定します。

## 実機確認

Xcode で6ターゲットに開発チームを指定します。レポート拡張は Family Controls、ウィジェットは App Group、残りの4ターゲットは両方を使います。登録済みの識別子を使う場合は `project.yml`、各ターゲットの entitlements、`Shared/ScreenTime.swift` をそろえます。

1. 初回起動で「許可してアプリを選ぶ」を押し、iOSで許可します。対象を選び、「今から1時間の制限を始める」を押すと、毎日この時間帯に制限する予定が保存されます。対象アプリを開き、制限画面が出るまで60秒以内か確認します。
2. 制限画面で「開かずに戻る」を押し、対象アプリが閉じ、ホームの今日の回数が1増えることを確認します。
3. 「10秒待って開く」を押し、10秒未満は制限が続き、その後は対象アプリだけを開けることを確認します。個別に選んだアプリと、選んだカテゴリ内のアプリで別々に試し、5分経過して端末を使ったときに制限が戻るか確認します。
4. 制限の開始・終了、選択外の曜日、日またぎを確認します。日付が変わると今日の回数が切り替わることと、一時解除せずに終了した制限日だけが連続日数に入ることを確認します。
5. 無料状態で「予定を追加」「回数の履歴と連続日数」「待ち時間とメッセージ」から購入画面が出ることを確認します。Pro の履歴では「開かずに戻る」の日別回数と連続日数を確認します。週比較は月曜から昨日までと先週の同じ曜日分を照合します。
6. Pro 状態で重なる時間帯を2件保存し、片方だけが終わっても制限が続くことを確認します。無料状態で予定外の時刻に集中時間を始め、アプリを閉じた状態でも指定時刻に制限が終わることを確認します。厳格モードでは制限画面に「10秒待って開く」が出ず、進行中に厳格モードを解除できないことを確認します。
7. テスト購入の更新時刻に2件目の予定がかかるようにします。アプリを閉じ、更新時刻を過ぎても制限が続くことを確認します。次に自動更新をオフにしてアプリを一度開き、期間終了後に1件目の予定だけに戻ることと、「利用時間を見る」を開けることを確認します。
8. 無料状態で「利用時間を見る」を開き、内訳の日別・週合計を、同じ端末のスクリーンタイム設定の対象アプリと照合します。比較には対象設定の翌日からの初週7日間と今週を使い、経過済みの同じ日数を比べます。記録の途中と直近で対象を使わなかった日を作り、0分として集計されることを確認します。比較の取得範囲は今週と直前5週です。初週が範囲外か取得できない場合も、今週の内訳は確認できます。
9. ホームとロック画面に「ひと呼吸」を追加します。対象アプリで「開かずに戻る」を押して回数が増えること、集中時間と制限予定の開始・終了で表示が変わること、日付が変わると回数が戻ることを確認します。更新のタイミングは iOS が管理します。
10. Pro で制限画面を一度表示し、制限中に待ち時間を20秒にし、メッセージを保存します。同じ対象アプリで文とボタンの表示が変わり、20秒経過後に開けることを確認します。Pro の失効後は標準の10秒とメッセージに戻ります。許可画面からアプリ選択まで、各画面で目的が読めることも確認します。

解除後、iOS の表示によっては対象アプリを開き直す操作が必要です。待機中に拡張が止まった場合は、もう一度同じボタンを押すと保存した開始時刻から判定します。再制限は iOS の DeviceActivity コールバックに依存するため、端末を操作中の場合とロックしている場合の両方で確認してください。

自動更新が確認済みなら、アプリを閉じたままでも期間終了から最長7日間は Pro の制限が続きます。アプリが購入状況を再確認すると、更新後の期限や失効が反映されます。

TestFlight と App Store の配布署名には、Family Controls を使うターゲットの配布承認が必要です。シミュレータのビルドと実機の開発署名は配布申請前に進められます。スクリーンタイムの許可、対象の選択、制限画面、解除と再制限は実機で確認します。[Apple の配布承認申請](https://developer.apple.com/contact/request/family-controls-distribution)
